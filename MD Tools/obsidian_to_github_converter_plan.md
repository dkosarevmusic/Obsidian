# Техническое Задание: Конвертер Obsidian Markdown в GitHub-совместимый формат

## 1. Цель

Создать Python-скрипт `obsidian_to_github_converter.py`, который автоматически преобразует Markdown-файл, созданный в Obsidian, в формат, оптимизированный для просмотра на GitHub.

## 2. Мотивация

Markdown-файлы из Obsidian часто содержат специфический синтаксис, который не поддерживается на GitHub:
-   **Внутренние ссылки-якоря:** `[[#Заголовок]]` не работают и отображаются как обычный текст.
-   **Блоки-цитаты (Callouts):** `> [!info]` и `> [!example]` теряют свое форматирование и выглядят как обычные цитаты.
-   **Длинные документы:** Большие файлы без сворачиваемых секций неудобны для навигации.

Скрипт должен решить эти проблемы, сделав документ читаемым и удобным для навигации на GitHub.

## 3. Ключевые Принципы

-   **Автономность:** Скрипт должен быть простым, од-но-фай-ло-вым, по аналогии с `convert_checkboxes_to_bullets.py` и `md creator.py`.
-   **In-place-редактирование:** Скрипт изменяет исходные файлы напрямую. Предполагается, что файлы в `working folder` являются копиями, поэтому создание отдельных `_github.md` файлов не требуется.
-   **Расположение:** Скрипт будет находиться в папке `MD Tools/` и работать с файлами в подпапке `working folder/`.
-   **Гибкость:** Логика должна быть реализована в виде отдельных функций для легкой поддержки и модификации.

## 4. План Реализации

Скрипт `obsidian_to_github_converter.py` будет состоять из трех основных частей:

### Шаг 1: Основная структура скрипта (по аналогии с `convert_checkboxes_to_bullets.py`)

Создать основной блок `if __name__ == "__main__":`, который:
1.  Определяет путь к папке `working folder` относительно расположения самого скрипта.
2.  Перебирает все файлы с расширением `.md` в этой папке.
3.  Для каждого файла:
    -   Читает его содержимое.
    -   Вызывает основную функцию-конвертер и получает измененное содержимое.
    -   Перезаписывает исходный файл этим содержимым.

```python
# Примерная структура

def main():
    script_dir = os.path.dirname(os.path.abspath(__file__))
    working_dir = os.path.join(script_dir, "working folder")

    for filename in os.listdir(working_dir):
        if filename.lower().endswith(".md"):
            input_path = os.path.join(working_dir, filename)

            with open(input_path, 'r', encoding='utf-8') as f:
                content = f.read()

            converted_content = convert_obsidian_to_github_md(content)

            with open(input_path, 'w', encoding='utf-8') as f:
                f.write(converted_content)
            print(f"Файл '{filename}' был успешно преобразован.")

if __name__ == "__main__":
    main()
```

### Шаг 2: Функция для генерации якорей (`generate_github_anchor`)

Эта функция будет отвечать за преобразование текста заголовка в GitHub-совместимую **ссылку-якорь (часть, идущая после `#`)**.

-   **Вход:** Строка (текст заголовка), например, `⚙️ Synth Techniques`.
-   **Логика:**
    1.  Привести строку к нижнему регистру.
    2.  Удалить все эмодзи (так как GitHub их удаляет при создании якорей).
    3.  Заменить пробелы на дефисы (`-`).
    4.  Удалить все символы, кроме букв, цифр и дефисов.
-   **Выход:** Очищенная строка, например, `synth-techniques`.

### Шаг 3: Основная функция-конвертер (`convert_obsidian_to_github_md`)

Эта функция будет выполнять все основные преобразования в два прохода.

#### Проход 1: Преобразование ссылок и callouts

1.  **Найти и полностью удалить блок навигации** (все строки, относящиеся к `> [!Navigation]`). Это делает отдельное оглавление ненужным.
3.  **Конвертировать Callouts:**
    -   Найти строки вида `> [!info] Заголовок`. Извлечь `Заголовок`.
    -   Заменить их на стандартный заголовок Markdown: `### Заголовок`.
    -   Аналогично для `> [!example] Заголовок`: заменить на `#### Заголовок`.
    -   Удалить префикс `> ` из всех строк внутри бывшего callout-блока, чтобы их содержимое стало обычным текстом.
4.  **Конвертировать чек-боксы в списки (по аналогии с `convert_checkboxes_to_bullets.py`):**
    -   Найти строки, содержащие чек-боксы (`- [ ]` или `- [x]`).
    -   Заменить их на обычные маркеры списка (`- `), сохраняя при этом все отступы и символы цитирования `>`.

#### Проход 2: Добавление сворачиваемых секций `<details>`

1.  Взять результат первого прохода.
2.  **Найти заголовки верхнего уровня** (`## Заголовок`).
2.  **Найти заголовки 1-го и 2-го уровня** (`# Заголовок` и `## Заголовок`).
3.  Для каждого такого заголовка:
    -   Открыть тег `<details>`. По умолчанию секция будет свернута.
    -   Использовать текст заголовка (включая эмодзи, но без символа '#') для тега `<summary>`, например: `<summary>🎛️ Music Sound-Design</summary>`.
    -   Все содержимое до следующего заголовка того же или более высокого уровня поместить внутрь блока `<details>`.
    -   Блоки для заголовков `##` будут вложены внутрь блоков для заголовков `#`.
    -   Закрыть тег `</details>`.
4.  **Исключения:** Блок `## Table of Contents` не должен оборачиваться в `<details>`.

## 5. Ожидаемый результат

После запуска скрипта все `*.md` файлы в папке `working folder` будут изменены и приведены в формат, полностью готовый к загрузке на GitHub (с рабочим оглавлением и сворачиваемыми разделами).
